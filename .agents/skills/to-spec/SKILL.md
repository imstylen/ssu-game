# To Spec

Read [the local workflow and spec template](../workflow.md). Inspect relevant code and decisions, reusing existing evidence.

Write or update `docs/work/<feature>/spec.md` with the problem, intended behavior, bounded scope, stable acceptance criteria, decisions, and proportionate verification. Include user stories only when they clarify behavior. Link relevant glossary entries and ADRs.

Synthesize rather than starting another interview. Record minor assumptions. Keep material unresolved decisions under open questions and leave the spec `draft`; ask only focused questions needed to unblock it. An actionable spec can be `ready` without another approval ritual.

Do not generate tickets or implement unless requested. Return the path, readiness, and material open decisions.
